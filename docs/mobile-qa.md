## Import retry hardening

- Summary retries reuse the original upload key for the same selected file or unchanged pasted text. A versioned result only opens the unconfirmed document with that exact key. Supporting-document retries read the current case snapshot, instead of reopening an older replay snapshot. The visible warning for an unavailable original names extracted text accurately.
- A local API test submitted a fictional PDF, added another document, and repeated the first upload key. The replay retained the original document ID; the live case retained both documents and only one stored copy of the invoice. Mobile regressions cover matching a document by ID, rejecting an unrelated or confirmed document, and the fallback for a legacy response.
- 131 backend tests, 19 mobile logic tests, TypeScript and the isolated PostgreSQL migration and access checks passed. The new retry code was not installed on the Samsung. An isolated Android run against a staging account is still needed to confirm a connection-loss retry through the screen, and a scan of a physical bill remains unverified. No production case or configuration was changed.
